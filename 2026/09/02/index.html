Accessibility Basics / 접근성 기초
🏠 Home / 홈 › Advanced / 고급 › Day 6

Goal (30–40 min): Make interactive components usable with a keyboard and a screen reader, using semantic elements, ARIA attributes, and useId.

목표 (30~40분): 시맨틱 엘리먼트, ARIA 속성, useId를 사용해서 키보드와 스크린 리더로도 사용 가능한 인터랙티브 컴포넌트를 만듭니다.

English

1. Use real semantic elements
A clickable <div onClick> gets none of the keyboard support, focus outline, or screen-reader semantics that a real <button> gets for free. Prefer <button>, <a href>, and form elements over generic <div>s with click handlers whenever there's a real semantic match.

2. ARIA describes state, not style
aria-expanded tells assistive tech whether a disclosure is open. aria-controls points a trigger at the id of the content it controls. Neither changes how anything looks — only what a screen reader announces.

3. useId
Accessibility attributes like aria-controls need a real, unique id to point at. const id = React.useId() generates one that's stable for the life of the component and safe even if the component renders more than once on the page.

한글

1. 진짜 시맨틱 엘리먼트를 쓰세요
클릭 가능한 <div onClick>은 진짜 <button>이 공짜로 얻는 키보드 지원, 포커스 아웃라인, 스크린 리더 시맨틱을 전혀 갖지 못합니다. 진짜 시맨틱 의미가 맞는 경우라면, 클릭 핸들러가 달린 일반 <div>보다 <button>, <a href>, 폼 엘리먼트를 선호하세요.

2. ARIA는 스타일이 아니라 상태를 설명합니다
aria-expanded는 disclosure가 열려있는지를 보조 기술에 알려줍니다. aria-controls는 트리거가 제어하는 콘텐츠의 id를 가리킵니다. 둘 다 무언가의 겉모습을 바꾸지 않고, 스크린 리더가 무엇을 읽어줄지만 바꿉니다.

3. useId
aria-controls 같은 접근성 속성은 가리킬 진짜 고유한 id가 필요합니다. const id = React.useId()는 컴포넌트가 살아있는 동안 안정적이고, 페이지에 두 번 이상 렌더링되어도 안전한 id를 생성합니다.
