Day 5 — 고급 (Advanced)

Higher-Order Components (HOCs) / 고차 컴포넌트
🏠 Home / 홈 › Advanced / 고급 › Day 5

Goal (30–40 min): Write a function that takes a component and returns a new, enhanced component — a pattern for reusing cross-cutting behavior across otherwise unrelated components.

목표 (30~40분): 컴포넌트를 받아서 기능이 추가된 새 컴포넌트를 반환하는 함수를 작성합니다 — 서로 관련 없는 컴포넌트들 사이에서 공통 동작을 재사용하는 패턴입니다.

English

1. A higher-order function, for components
You already know higher-order functions — ones that take or return other functions (like Array.map). A higher-order component is the same idea: a function that takes a component and returns a new component wrapping it.

2. The shape
function withLoading(Component) { return function WithLoading(props) { ... } }. The returned component decides what to render — often the original Component with all the same props spread onto it (<Component {...props} />), plus some extra behavior wrapped around it.

3. When to reach for it (vs. hooks)
Custom hooks (Intermediate Day 2) are usually the better tool today for sharing logic. HOCs still shine for sharing entire rendering decisions — like "show a loading state instead of the real component" — across many different components.

한글

1. 컴포넌트를 위한 고차 함수
이미 고차 함수(다른 함수를 받거나 반환하는 함수, 예: Array.map)는 알고 계실 겁니다. 고차 컴포넌트도 같은 아이디어입니다: 컴포넌트를 받아서 그것을 감싼 새 컴포넌트를 반환하는 함수입니다.

2. 모양
function withLoading(Component) { return function WithLoading(props) { ... } }. 반환된 컴포넌트가 무엇을 렌더링할지 결정합니다 — 보통 원본 Component에 동일한 props를 그대로 펼쳐서(<Component {...props} />) 전달하고, 그 주변에 추가 동작을 감쌉니다.

3. 언제 쓸까 (훅과 비교해서)
커스텀 훅(중급 2일차)이 요즘은 로직 공유에 보통 더 나은 도구입니다. HOC는 여러 다른 컴포넌트에 걸쳐 "로딩 상태를 실제 컴포넌트 대신 보여주기"처럼 전체 렌더링 결정을 공유할 때 여전히 빛을 발합니다.

Live example / 실시간 예제

withLoading wraps UserList so it shows a spinner instead, whenever isLoading is true.

withLoading이 UserList를 감싸서, isLoading이 true일 때는 스피너를 대신 보여줍니다.
