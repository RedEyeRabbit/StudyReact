Model solution for the RTL test / RTL 테스트 모범 답안
🏠 Home / 홈 › Day 7 Lesson / 학습 › Answer / 답안

Explanation

getByRole("button", { name: "Log in" }) both finds the element and asserts it exists — if no button with that accessible name is on screen, RTL throws, which is exactly why simply calling it (without wrapping in expect) works as an assertion for TODO 1. fireEvent.click simulates the real click. Querying again afterward for "Log out" proves the state actually changed — not by inspecting internal state, but by checking what a user would now see.

설명

getByRole("button", { name: "Log in" })는 엘리먼트를 찾음과 동시에 존재를 검증합니다 — 해당 접근성 이름을 가진 버튼이 화면에 없으면 RTL이 예외를 던지므로, TODO 1에서 expect로 감싸지 않고 그냥 호출하는 것만으로도 검증 역할을 합니다. fireEvent.click이 실제 클릭을 흉내냅니다. 이후 "Log out"을 다시 조회하는 것은 내부 state를 들여다보는 게 아니라, 사용자가 이제 실제로 보게 될 것을 확인해서 state가 정말로 바뀌었음을 증명합니다.

The completed test / 완성된 테스트

import { render, screen, fireEvent } from "@testing-library/react";
import { expect, test } from "vitest";
import LoginButton from "./LoginButton.jsx";

test("toggles between Log in and Log out when clicked", () => {
  render(<LoginButton />);

  expect(screen.getByRole("button", { name: "Log in" })).toBeInTheDocument();

  fireEvent.click(screen.getByRole("button"));

  expect(screen.getByRole("button", { name: "Log out" })).toBeInTheDocument();
});
