State & Events (useState) / State와 이벤트 처리 (useState)
🏠 Home / 홈 › Beginner / 초급 › Day 3

Goal (30–40 min): Understand why components need state, use the useState hook, and handle click events.

목표 (30~40분): 컴포넌트에 왜 state가 필요한지 이해하고, useState 훅을 사용하며, 클릭 이벤트를 처리합니다.

English

1. Props vs. State
Props come from a parent and never change inside the component. State is data a component owns and can change over time — for example, whether a button has been clicked. When state changes, React automatically re-renders the component.

2. The useState hook
const [value, setValue] = useState(initialValue) returns the current value and a setter function. Call the setter to update the value — never assign to it directly.

3. Event handlers
JSX uses camelCase event props like onClick, onChange. You pass a function, not a function call: onClick={handleClick}, not onClick={handleClick()}.

한글

1. Props vs. State
Props는 부모로부터 전달받으며 컴포넌트 내부에서 절대 바뀌지 않습니다. State는 컴포넌트가 스스로 소유하고 시간에 따라 바뀔 수 있는 데이터입니다 — 예를 들어 버튼이 클릭되었는지 여부. state가 바뀌면 React가 자동으로 컴포넌트를 다시 렌더링합니다.

2. useState 훅
const [value, setValue] = useState(initialValue)는 현재 값과 값을 바꾸는 setter 함수를 반환합니다. 값을 바꿀 때는 반드시 setter를 호출해야 하며, 절대 직접 대입하면 안 됩니다.

3. 이벤트 처리
JSX는 onClick, onChange처럼 camelCase 이벤트 prop을 사용합니다. 함수를 호출한 결과가 아니라 함수 자체를 전달해야 합니다: onClick={handleClick()}가 아니라 onClick={handleClick}.

Common pitfalls

  • Don't mutate state directly (count++) — always call the setter (setCount(count + 1)).
  • Don't call the handler function in JSX (onClick={fn()}) — pass the function reference (onClick={fn}).
  • Each component instance has its own independent state.

흔한 실수

  • state를 직접 변경하지 마세요 (count++) — 항상 setter를 호출하세요 (setCount(count + 1)).
  • JSX에서 핸들러 함수를 호출하지 마세요 (onClick={fn()}) — 함수 참조를 전달하세요 (onClick={fn}).
  • 각 컴포넌트 인스턴스는 독립적인 자신만의 state를 가집니다.
