Goal (30–40 min): Understand what client-side routing is, and see it two ways: a hand-built mini router here, and the real react-router-dom library in the Node.js lab.

목표 (30~40분): 클라이언트 사이드 라우팅이 무엇인지 이해하고, 두 가지 방식으로 봅니다: 여기서는 직접 만든 미니 라우터, Node.js Lab에서는 실제 react-router-dom 라이브러리.

English

1. What client-side routing means
Instead of asking the server for a whole new HTML page every time you navigate (slow, loses all React state), a "router" swaps which component renders based on the current URL/path — no full reload.

2. About this lesson's example
The browser playground here can't easily load react-router-dom from a CDN, so it demonstrates the concept with a tiny hand-built router: a piece of state holding the "current path," and links that update it instead of navigating. Real apps use a battle-tested library instead of reinventing this.

3. The real thing
Practical Lab has real npm installed react-router-dom, with <Routes>, <Route>, <Link>, and useParams() for reading URL segments like an ID. Try today's exercise there to see it for real.

한글

1. 클라이언트 사이드 라우팅이란
페이지를 이동할 때마다 서버에 완전히 새로운 HTML 페이지를 요청하는 대신(느리고, React state가 모두 사라짐), "라우터"는 현재 URL/경로에 따라 어떤 컴포넌트를 렌더링할지 바꿔치기합니다 — 전체 새로고침 없이.

2. 이번 레슨 예제에 대해
여기 브라우저 플레이그라운드는 CDN에서 react-router-dom을 쉽게 불러올 수 없어서, "현재 경로"를 담는 state 하나와, 이동하는 대신 그 state를 바꾸는 링크들로 개념을 직접 만든 작은 라우터로 보여줍니다. 실제 앱은 이걸 처음부터 다시 만들지 않고 검증된 라이브러리를 사용합니다.

3. 진짜배기
Practical Lab에는 실제로 npm install한 react-router-dom이 있어서 <Routes>, <Route>, <Link>, ID 같은 URL 조각을 읽는 useParams()를 씁니다. 오늘 실습은 거기서 진짜로 해보세요.
