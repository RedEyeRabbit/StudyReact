Day 5 — 초급 (Beginner)

Lists & Keys / 리스트와 Key
🏠 Home / 홈 › Beginner / 초급 › Day 5

Goal (30–40 min): Render arrays as lists correctly and understand why the key prop matters when a list can change.

목표 (30~40분): 배열을 리스트로 올바르게 렌더링하고, 리스트가 변경될 수 있을 때 key prop이 왜 중요한지 이해합니다.

English

1. Why keys matter
When a list re-renders, React uses each item's key to match it to the same item from the previous render. Without stable keys, React can't tell which item was added, removed, or reordered — it may reuse the wrong DOM node and mix up state that belongs to a specific row (like an input's typed text).

2. What makes a good key
A key must be unique among siblings and stable across renders — ideally an ID that already exists in your data (todo.id), not something regenerated every render.

3. Array index as key
Using the array index (key={index}) only works safely for lists that never get reordered, filtered, or have items inserted anywhere but the end. Prefer a real ID whenever the list can change shape.

한글

1. key가 중요한 이유
리스트가 다시 렌더링될 때, React는 각 항목의 key를 이용해 이전 렌더링의 같은 항목과 매칭합니다. 안정적인 key가 없으면 React는 어떤 항목이 추가/삭제/순서 변경되었는지 알 수 없어서, 잘못된 DOM 노드를 재사용하며 특정 행에 속한 state(예: 입력창에 입력한 텍스트)가 뒤섞일 수 있습니다.

2. 좋은 key의 조건
key는 형제 요소들 사이에서 고유해야 하고, 렌더링마다 안정적이어야 합니다 — 매번 새로 만드는 값이 아니라, 데이터에 이미 존재하는 ID(todo.id)를 쓰는 게 이상적입니다.

3. 배열 인덱스를 key로 쓰기
배열 인덱스를 key로 쓰는 것(key={index})은 리스트 순서가 절대 바뀌지 않고, 맨 끝이 아닌 곳에 항목이 추가/삭제되지 않는 경우에만 안전합니다. 리스트 모양이 바뀔 수 있다면 진짜 ID를 쓰세요.
