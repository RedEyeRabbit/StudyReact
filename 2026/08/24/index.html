Day 9 — 중급 (Intermediate)

Debouncing & Combining Hooks / 디바운싱과 훅 조합
🏠 Home / 홈 › Intermediate / 중급 › Day 9

Goal (30–40 min): Build a useDebounce custom hook, and combine it with the fetch pattern from Day 1–2 for search-as-you-type.

목표 (30~40분): useDebounce 커스텀 훅을 만들고, 1~2일차의 fetch 패턴과 조합해서 입력하는 대로 검색되는 기능을 만듭니다.

English

1. Why debounce
Searching "on every keystroke" would fire a request per character — wasteful, and results can arrive out of order (Day 1 already showed how to guard against that, but it's better to avoid firing so many requests in the first place).

2. The debounce idea
Only act after the value has stopped changing for a bit. A useDebounce(value, delay) hook returns a copy of value that lags behind — it schedules a timeout to update on every change, but cancels the previous timeout each time (via the cleanup function), so only the last one actually fires.

3. Combining what you've learned
The search component below uses useState for the raw input, useDebounce to calm it down, and an effect (like Day 1/2) that fetches whenever the debounced value changes — three ideas from this week working together.

한글

1. 디바운스가 필요한 이유
"키를 누를 때마다" 검색하면 글자 하나마다 요청이 나갑니다 — 낭비이고, 응답 순서가 뒤바뀔 수도 있습니다(1일차에서 이미 방지법을 봤지만, 애초에 요청을 그렇게 많이 보내지 않는 게 더 낫습니다).

2. 디바운스의 아이디어
값이 잠시 동안 안 바뀌었을 때만 반응하세요. useDebounce(value, delay) 훅은 뒤처진 value 사본을 반환합니다 — 값이 바뀔 때마다 갱신용 타임아웃을 예약하지만, 매번 (cleanup 함수로) 이전 타임아웃을 취소하므로 마지막 것만 실제로 실행됩니다.

3. 배운 것들을 조합하기
아래 검색 컴포넌트는 원본 입력에 useState를, 진정시키는 데 useDebounce를, 디바운스된 값이 바뀔 때마다 fetch하는 effect(1~2일차와 동일)를 사용합니다 — 이번 주에 배운 세 가지 아이디어가 함께 동작합니다.

Live example / 실시간 예제

Type a name — the search only fires 400ms after you stop typing.

이름을 입력해보세요 — 타이핑을 멈춘 지 400ms 후에만 검색이 실행됩니다.
