Model solution for ExpensiveList / ExpensiveList 모범 답안
🏠 Home / 홈 › Day 6 Lesson / 학습 › Answer / 답안

Explanation

All three memoizations have to work together: React.memo only skips a re-render if every prop is reference-equal to last time. If items or onSelect were freshly created on each App render (a new array literal, a new arrow function), memo would see "different" props and re-render anyway — useMemo/useCallback are what make those references actually stay stable.

설명

세 가지 메모이제이션이 함께 작동해야 합니다: React.memo는 모든 prop이 지난번과 참조상 동일할 때만 리렌더링을 건너뜁니다. 만약 items나 onSelect가 App이 렌더링될 때마다 새로 만들어진다면(새 배열 리터럴, 새 화살표 함수), memo는 "다른" props로 보고 어차피 다시 렌더링합니다 — useMemo/useCallback이 바로 그 참조들을 실제로 안정적으로 유지시켜주는 역할입니다.

Self-check

  • Does typing in the input leave "ExpensiveList has rendered 1 time(s)" unchanged, no matter how much you type?
  • Does clicking a list item still update "Selected"?
  • Would removing just one of the three memoizations (try it!) make the render count climb again?

스스로 점검하기

  • 입력창에 아무리 타이핑해도 "ExpensiveList has rendered 1 time(s)"가 그대로인가요?
  • 리스트 항목을 클릭하면 여전히 "Selected"가 갱신되나요?
  • 세 메모이제이션 중 하나만 제거하면(직접 해보세요!) 렌더 횟수가 다시 올라가나요?
