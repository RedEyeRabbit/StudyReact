Day 6 — 중급 (Intermediate)

Performance: memo, useMemo, useCallback / 성능 최적화
🏠 Home / 홈 › Intermediate / 중급 › Day 6

Goal (30–40 min): Skip unnecessary re-renders and recalculations with React.memo, useMemo, and useCallback.

목표 (30~40분): React.memo, useMemo, useCallback으로 불필요한 리렌더링과 재계산을 건너뜁니다.

English

1. The default: everything re-renders
When a parent re-renders, every child re-renders too, by default — even ones whose props didn't change. Usually that's fine (React is fast), but for expensive children it can be wasteful.

2. React.memo
const Fast = React.memo(SlowComponent) skips re-rendering Fast if its props are shallow-equal to last time. This only helps if the props actually stay the same reference — a new inline object or function prop defeats it.

3. useMemo & useCallback
useMemo(() => computeExpensive(x), [x]) only recomputes when x changes. useCallback(fn, deps) is the same idea for functions — it keeps returning the same function reference across renders as long as deps hasn't changed, which is exactly what a memo-wrapped child needs to actually skip re-rendering.

한글

1. 기본값: 모두 리렌더링
부모가 리렌더링되면 기본적으로 모든 자식도 리렌더링됩니다 — props가 바뀌지 않은 자식도 마찬가지입니다. 보통은 문제없지만 (React는 빠릅니다), 무거운 자식에게는 낭비일 수 있습니다.

2. React.memo
const Fast = React.memo(SlowComponent)는 props가 지난번과 얕은 비교(shallow-equal)로 같으면 Fast의 리렌더링을 건너뜁니다. props가 실제로 같은 참조를 유지할 때만 도움이 되며, 매번 새로 만드는 인라인 객체나 함수 prop은 이 효과를 무력화시킵니다.

3. useMemo와 useCallback
useMemo(() => computeExpensive(x), [x])는 x가 바뀔 때만 다시 계산합니다. useCallback(fn, deps)는 함수 버전의 같은 아이디어로, deps가 안 바뀌는 한 렌더링 사이에 같은 함수 참조를 계속 반환합니다 — 이게 바로 memo로 감싼 자식이 실제로 리렌더링을 건너뛰기 위해 필요한 것입니다.
