Day 1 — 중급 (Intermediate)

useEffect & Fetching Data / useEffect와 데이터 가져오기
🏠 Home / 홈 › Intermediate / 중급 › Day 1

Goal (30–40 min): Fetch async data inside useEffect with proper loading/error state, and avoid updating state from a stale request.

목표 (30~40분): useEffect 안에서 비동기 데이터를 가져오면서 loading/error state를 제대로 관리하고, 오래된(stale) 요청이 state를 덮어쓰지 않도록 합니다.

English

1. Note on examples this level
From here on, "network calls" are simulated with a mock function that resolves after a short delay — same shape as a real fetch(), but works offline and is deterministic to test. Swapping in a real API call later is a one-line change.

2. The async-effect problem
The function passed to useEffect can't be async itself — React expects it to return either nothing or a cleanup function, not a Promise. Define an async function inside the effect and call it immediately.

3. Guarding against stale responses
If userId changes before the first request finishes, two responses can arrive out of order. Use an ignore flag set in the cleanup function so a late response from an old request is ignored.

한글

1. 이번 레벨 예제에 대한 안내
여기서부터 "네트워크 호출"은 짧은 지연 후 resolve되는 모의(mock) 함수로 흉내냅니다 — 실제 fetch()와 모양은 같지만 오프라인에서도 동작하고 테스트하기 결정적(deterministic)입니다. 나중에 진짜 API 호출로 바꾸는 건 한 줄만 고치면 됩니다.

2. 비동기 effect의 문제
useEffect에 전달하는 함수 자체는 async일 수 없습니다 — React는 이 함수가 아무것도 반환하지 않거나 cleanup 함수를 반환하길 기대하지, Promise를 기대하지 않습니다. effect 내부에 async 함수를 정의하고 바로 호출하세요.

3. 오래된 응답 방지
첫 요청이 끝나기 전에 userId가 바뀌면, 응답 두 개가 순서가 뒤바뀌어 도착할 수 있습니다. cleanup 함수에서 ignore 플래그를 설정해서, 오래된 요청에서 늦게 온 응답은 무시하세요.
