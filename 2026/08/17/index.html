Day 4 — 중급 (Intermediate)

useReducer
🏠 Home / 홈 › Intermediate / 중급 › Day 4

Goal (30–40 min): Manage state with multiple related transitions using useReducer instead of several separate useState calls.

목표 (30~40분): 여러 개의 useState 대신 useReducer로 서로 연관된 여러 state 전이를 관리합니다.

English

1. When useState starts to strain
A shopping cart needs to add items, remove items, and clear everything. You could juggle this with useState plus a handful of update functions, but the logic for "how state changes" ends up scattered across the component.

2. The reducer pattern
const [state, dispatch] = useReducer(reducer, initialState). A reducer is a function (state, action) => newState — it never mutates state, only returns a new value. Instead of calling setters directly, components call dispatch({ type: "ADD_ITEM", item }), and the reducer decides what the next state looks like.

3. Why this helps
All the state-transition logic lives in one place (the reducer), described as a list of named actions — easier to read, test, and reason about than update logic spread across many handlers.

한글

1. useState가 버거워지는 시점
장바구니는 항목 추가, 항목 삭제, 전체 비우기가 필요합니다. useState와 몇 개의 갱신 함수로 이걸 처리할 수도 있지만, "state가 어떻게 바뀌는지"에 대한 로직이 컴포넌트 여기저기 흩어지게 됩니다.

2. 리듀서 패턴
const [state, dispatch] = useReducer(reducer, initialState). 리듀서는 (state, action) => newState 형태의 함수입니다 — state를 절대 변경하지 않고, 새 값만 반환합니다. setter를 직접 호출하는 대신, 컴포넌트는 dispatch({ type: "ADD_ITEM", item })를 호출하고, 다음 state가 어떤 모습일지는 리듀서가 결정합니다.

3. 왜 도움이 되는가
모든 state 전이 로직이 한 곳(리듀서)에, 이름 붙은 액션들의 목록으로 정리됩니다 — 여러 핸들러에 흩어진 갱신 로직보다 읽고, 테스트하고, 추론하기 쉽습니다.
