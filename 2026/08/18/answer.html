Model solution for SearchInput / SearchInput 모범 답안
🏠 Home / 홈 › Day 5 Lesson / 학습 › Answer / 답안

Explanation

The mount-only effect ([]) calls inputRef.current.focus() once, right after the input exists in the DOM. The second effect runs after every render where text changed, and updates previousRef.current — but since effects run after the render commits, the value read during the next render is always one step behind, which is exactly "the previous value."

설명

마운트 전용 effect([])는 input이 DOM에 존재하게 된 직후 inputRef.current.focus()를 한 번 호출합니다. 두 번째 effect는 text가 바뀐 렌더링 이후마다 실행되어 previousRef.current를 갱신하는데, effect는 렌더링이 커밋된 이후에 실행되기 때문에, 다음 렌더링에서 읽는 값은 항상 한 단계 뒤처져 있고, 이것이 정확히 "이전 값"입니다.

Self-check

  • Is the input already focused the moment the page loads, with no click needed?
  • Does the "Previous value" label always show what you typed before your latest keystroke, not the current text?
  • Does typing avoid extra re-renders caused by the ref itself (refs don't trigger renders)?

스스로 점검하기

  • 페이지가 로드되는 순간 클릭 없이도 입력창에 이미 포커스가 가 있나요?
  • "Previous value" 라벨이 항상 현재 텍스트가 아니라 가장 최근 입력 전에 입력했던 값을 보여주나요?
  • ref 자체 때문에 발생하는 불필요한 리렌더링이 없나요(ref는 렌더링을 유발하지 않음)?
