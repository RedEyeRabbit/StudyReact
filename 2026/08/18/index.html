Day 5 — 중급 (Intermediate)

Refs & useRef
🏠 Home / 홈 › Intermediate / 중급 › Day 5

Goal (30–40 min): Use useRef for two different jobs: reaching a real DOM node, and storing a mutable value that survives re-renders without causing one.

목표 (30~40분): useRef의 두 가지 용도를 익힙니다: 실제 DOM 노드에 접근하기, 그리고 리렌더링을 유발하지 않으면서 렌더링 사이에 값을 유지하기.

English

1. Accessing a DOM node
const inputRef = useRef(null), then <input ref={inputRef} />. After the DOM is painted, inputRef.current is the actual <input> element — call inputRef.current.focus() to focus it, typically from inside a useEffect.

2. Persisting a mutable value
useRef(initialValue) also works as a plain "box" that keeps a value across renders. Unlike state, changing ref.current does not trigger a re-render — useful for values the render output doesn't depend on, like a timer ID or the previous value of a prop.

3. Ref vs. state, in one line
Need the screen to update when it changes? Use state. Just need to remember something between renders without redrawing anything? Use a ref.

한글

1. DOM 노드에 접근하기
const inputRef = useRef(null)을 만들고, <input ref={inputRef} />처럼 씁니다. DOM이 그려진 후 inputRef.current는 실제 <input> 엘리먼트이며, 보통 useEffect 안에서 inputRef.current.focus()를 호출해 포커스를 줍니다.

2. 변경 가능한 값 유지하기
useRef(initialValue)는 렌더링 사이에 값을 유지하는 평범한 "상자"로도 쓸 수 있습니다. state와 달리 ref.current를 바꿔도 리렌더링이 일어나지 않습니다 — 렌더링 결과가 의존하지 않는 값, 예를 들어 타이머 ID나 prop의 이전 값을 저장할 때 유용합니다.

3. Ref vs. state, 한 줄 요약
값이 바뀔 때 화면이 갱신되어야 하나요? state를 쓰세요. 화면을 다시 그릴 필요 없이 렌더링 사이에 뭔가를 기억만 하면 되나요? ref를 쓰세요.

Live example / 실시간 예제

An input that auto-focuses on mount, and a label showing the previous value you typed — tracked with a ref, not state.

마운트 시 자동으로 포커스되는 입력창과, 입력했던 이전 값을 보여주는 라벨입니다 — state가 아니라 ref로 추적합니다.
