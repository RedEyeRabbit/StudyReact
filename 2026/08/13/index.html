Day 2 — 중급 (Intermediate)

Custom Hooks / 커스텀 훅
🏠 Home / 홈 › Intermediate / 중급 › Day 2

Goal (30–40 min): Extract Day 1's fetch-with-loading logic into a reusable custom hook.

목표 (30~40분): 1일차의 fetch+loading 로직을 재사용 가능한 커스텀 훅으로 추출합니다.

English

1. What makes a hook a hook
A custom hook is just a normal JavaScript function whose name starts with use, and which calls other hooks inside it. That naming convention is what lets React (and linters) know it follows the rules of hooks.

2. Why bother
Day 1's UserProfile mixed two concerns: fetching data, and rendering it. A custom hook lets you pull out "fetching data" as reusable logic, so any component can get { user, loading } in one line, without duplicating the effect.

3. Rules of hooks (recap)
Only call hooks at the top level of a function — never inside a loop, condition, or nested function. This applies the same way whether the hook is built-in (useState) or custom.

한글

1. 훅을 훅답게 만드는 것
커스텀 훅은 이름이 use로 시작하고 그 안에서 다른 훅을 호출하는, 그냥 평범한 JavaScript 함수입니다. 이 이름 규칙 덕분에 React(와 린터)가 이 함수가 훅의 규칙을 따른다는 걸 압니다.

2. 왜 필요한가
1일차의 UserProfile은 두 가지 관심사가 섞여 있었습니다: 데이터 가져오기와 렌더링. 커스텀 훅을 쓰면 "데이터 가져오기"를 재사용 가능한 로직으로 뽑아낼 수 있어서, 어떤 컴포넌트든 effect를 중복 작성하지 않고 한 줄로 { user, loading }를 얻을 수 있습니다.

3. 훅의 규칙 (복습)
훅은 함수의 최상위에서만 호출하세요 — 반복문, 조건문, 중첩 함수 안에서는 절대 호출하지 마세요. 내장 훅(useState)이든 커스텀 훅이든 똑같이 적용됩니다.
