Day 7 — 초급 (Beginner)

Lifting State Up / State 끌어올리기
🏠 Home / 홈 › Beginner / 초급 › Day 7

Goal (30–40 min): Share one piece of state between sibling components by moving it up to their common parent.

목표 (30~40분): 하나의 state를 형제 컴포넌트끼리 공유하기 위해 공통 부모로 끌어올립니다.

English

1. The problem
Sibling components can't talk to each other directly — a component only knows about its own state and the props its parent gives it. If two siblings need to reflect the same data, neither one can "own" it alone.

2. The fix: lift state up
Move the state to their closest common parent. The parent passes the current value down to both children as props, and passes down callback functions (like onAdd, onRemove) so children can ask the parent to update it. This is sometimes summarized as "data flows down, actions flow up."

3. You've already been doing this
Every playground since Day 5 already lifts state up: App owns the items array, and passes it (plus update callbacks) down to ShoppingList and AddItemForm — two separate sibling components sharing one source of truth.

한글

1. 문제 상황
형제 컴포넌트끼리는 서로 직접 대화할 수 없습니다 — 컴포넌트는 자기 자신의 state와 부모가 준 props만 알 수 있습니다. 두 형제가 같은 데이터를 반영해야 한다면, 둘 중 누구도 그 데이터를 혼자 "소유"할 수 없습니다.

2. 해결책: state 끌어올리기
state를 가장 가까운 공통 부모로 옮기세요. 부모는 현재 값을 두 자식 모두에게 props로 내려주고, 자식이 값을 바꿔달라고 요청할 수 있도록 콜백 함수(onAdd, onRemove 같은)도 함께 내려줍니다. 흔히 "데이터는 아래로, 액션은 위로"라고 요약합니다.

3. 이미 하고 있었습니다
5일차부터 모든 플레이그라운드가 이미 이 패턴을 쓰고 있었습니다: App이 items 배열을 소유하고, 이를 (그리고 갱신용 콜백을) ShoppingList와 AddItemForm이라는 별개의 두 형제 컴포넌트에 내려줘서, 하나의 진실 공급원을 함께 공유합니다.

Live example / 실시간 예제

A third sibling, ItemCount, joins ShoppingList and AddItemForm — all three read from or update the same items state living in App.

세 번째 형제 ItemCount가 ShoppingList, AddItemForm과 합류합니다 — 셋 다 App에 있는 같은 items state를 읽거나 갱신합니다.
