Model solution for the User Search app / 사용자 검색 앱 모범 답안
🏠 Home / 홈 › Day 10 Lesson / 학습 › Answer / 답안

Explanation

useUserSearch is Day 1's async-effect pattern again, just fed a debounced query instead of a raw one, and packaged as a hook (Day 2) so UserSearchApp gets { user, loading } in one line. The content if/else chain is ordinary conditional rendering — four mutually exclusive states, checked in an order that makes sense (empty query first, then loading, then found vs. not found).

설명

useUserSearch는 1일차의 비동기 effect 패턴을 그대로 다시 쓴 것이며, 다만 원본 대신 디바운스된 query를 받고, (2일차처럼) 훅으로 포장되어 UserSearchApp이 { user, loading }을 한 줄로 얻습니다. content의 if/else 체인은 평범한 조건부 렌더링입니다 — 서로 배타적인 네 가지 상태를, 말이 되는 순서로(빈 query 먼저, 그다음 로딩, 그다음 찾음/못찾음) 확인합니다.
