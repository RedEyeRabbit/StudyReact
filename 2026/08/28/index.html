Day 3 — 고급 (Advanced)

Render Props / 렌더 프롭
🏠 Home / 홈 › Advanced / 고급 › Day 3

Goal (30–40 min): Share stateful behavior between components while letting each caller decide what to render, using the render props pattern.

목표 (30~40분): 상태를 가진 동작(behavior)은 컴포넌트끼리 공유하면서, 실제로 무엇을 렌더링할지는 호출하는 쪽이 정하도록 하는 render props 패턴을 익힙니다.

English

1. The problem
Say several different UIs all need "track the mouse position" or "track whether the user is hovering." The logic is identical every time, but what to render with that data is different everywhere.

2. The pattern
Instead of hard-coding what a component renders, give it a prop that is a function — the component calls that function with its internal state, and renders whatever it returns. The component owns the "how to track," the caller owns the "what to show."

3. Naming it
This prop is often literally called render, but any name works — even children (called as props.children(state), with the function passed between the JSX tags) is a common variant.

한글

1. 문제 상황
서로 다른 여러 UI가 모두 "마우스 위치 추적"이나 "사용자가 hover 중인지 추적"이 필요하다고 해봅시다. 로직은 매번 동일하지만, 그 데이터로 무엇을 렌더링할지는 매번 다릅니다.

2. 패턴
컴포넌트가 무엇을 렌더링할지 하드코딩하는 대신, 함수인 prop을 넘겨주세요 — 컴포넌트는 자신의 내부 state로 그 함수를 호출하고, 반환된 것을 렌더링합니다. "어떻게 추적할지"는 컴포넌트가, "무엇을 보여줄지"는 호출하는 쪽이 소유합니다.

3. 이름 붙이기
이 prop은 흔히 문자 그대로 render라고 부르지만, 어떤 이름이든 상관없습니다 — children(JSX 태그 사이에 함수를 넣어 props.children(state)로 호출)도 흔한 변형입니다.

Live example / 실시간 예제

MouseTracker owns the mouse-tracking logic; App decides what to show with the position.

MouseTracker가 마우스 추적 로직을 소유하고, App이 그 위치로 무엇을 보여줄지 결정합니다.
