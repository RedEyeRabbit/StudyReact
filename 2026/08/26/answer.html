Model solution for the store / 스토어 모범 답안
🏠 Home / 홈 › Day 1 Lesson / 학습 › Answer / 답안

Explanation

setState checks whether it was given a function (compute the next state from the current one) or a plain object (merge it in) — then loops over every registered listener and calls it, which is how React finds out something changed. subscribe is just Set.add plus a matching Set.delete in the returned cleanup. useSyncExternalStore ties it together: whenever a listener fires, React re-reads getState() and re-renders if it changed.

설명

setState는 받은 것이 함수(현재 state로부터 다음 state 계산)인지 평범한 객체(병합)인지 확인한 다음, 등록된 모든 listener를 순회하며 호출합니다 — 이것이 React가 무언가 바뀌었다는 걸 알게 되는 방법입니다. subscribe는 그냥 Set.add와, 반환하는 cleanup 안의 짝이 되는 Set.delete일 뿐입니다. useSyncExternalStore가 이 모든 것을 연결합니다: listener가 실행될 때마다 React는 getState()를 다시 읽고, 바뀌었다면 다시 렌더링합니다.

Self-check

  • Does clicking +1 update the count shown by a totally separate sibling component?
  • Does Reset bring it back to 0?
  • Could a third, unrelated component elsewhere on the page also read this same store, with zero props passed anywhere?

  • Reset을 누르면 0으로 돌아가나요?
  • 페이지 어딘가의 완전히 관련 없는 세 번째 컴포넌트도 props 전달 없이 같은 스토어를 읽을 수 있을까요?
