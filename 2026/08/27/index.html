Code Splitting & Lazy Loading / 코드 스플리팅과 지연 로딩
🏠 Home / 홈 › Advanced / 고급 › Day 2

Goal (30–40 min): Load a component's code only when it's actually needed, using React.lazy and <Suspense>.

목표 (30~40분): React.lazy와 <Suspense>로 컴포넌트 코드를 실제로 필요할 때만 불러옵니다.

English

1. Why split code at all
Every component you import ends up in the JavaScript bundle the browser has to download before your app can run. A rarely-used, heavy component (a chart library, an admin panel) shouldn't slow down the initial load for users who may never see it.

2. React.lazy
const LazyChart = React.lazy(() => import("./Chart.jsx")) wraps a dynamic import() — the module is only fetched the first time LazyChart actually renders, not when the file that defines it loads.

3. Suspense
While the lazy component's code is being fetched, React needs something to show — wrap it in <Suspense fallback={}>. The fallback shows until the import resolves, then React swaps in the real component.

한글

1. 코드를 나누는 이유
import한 모든 컴포넌트는 결국 브라우저가 앱을 실행하기 전에 다운로드해야 하는 JavaScript 번들에 포함됩니다. 어쩌다 한 번 쓰이는 무거운 컴포넌트(차트 라이브러리, 관리자 패널)가 그걸 절대 보지 않을 수도 있는 사용자의 초기 로딩까지 느리게 만들면 안 됩니다.

2. React.lazy
const LazyChart = React.lazy(() => import("./Chart.jsx"))는 동적 import()를 감쌉니다 — 모듈은 LazyChart를 정의한 파일이 로드될 때가 아니라, LazyChart가 실제로 렌더링되는 첫 순간에만 가져와집니다.

3. Suspense
지연 컴포넌트의 코드를 가져오는 동안 React는 뭔가 보여줄 게 필요합니다 — <Suspense fallback={}>로 감싸세요. import가 완료될 때까지 fallback이 보이다가, React가 실제 컴포넌트로 바꿔치기합니다.

About this lesson's example

The browser playground here fakes the delay with a Promise (there's no separate file to actually split in a single pasted script). Practical Lab's version does real code splitting — a genuinely separate file, fetched as its own chunk by Vite.

이번 레슨 예제에 대해

여기 브라우저 플레이그라운드는 지연을 Promise로 흉내냅니다 (하나로 붙여넣은 스크립트 안에는 실제로 분리할 별도 파일이 없으니까요). Practical Lab 버전은 진짜 코드 스플리팅을 합니다 — 실제로 분리된 파일을 Vite가 별도 청크로 가져옵니다.
