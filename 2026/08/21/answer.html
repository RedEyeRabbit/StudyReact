Model solution for ErrorBoundary / ErrorBoundary 모범 답안
🏠 Home / 홈 › Day 8 Lesson / 학습 › Answer / 답안

Explanation

getDerivedStateFromError runs during the "render" phase right after a child throws, and its return value becomes the boundary's new state — returning { hasError: true } is what tells React "render me differently now." render() then checks that flag: if set, it shows the fallback instead of this.props.children, so the broken Buggy never actually gets rendered again.

설명

getDerivedStateFromError는 자식이 에러를 던진 직후 "렌더링" 단계에서 실행되며, 반환값이 바운더리의 새 state가 됩니다 — { hasError: true }를 반환하는 것이 React에게 "이제 다르게 렌더링해라"라고 알려주는 방법입니다. render()는 그 플래그를 확인해서, 설정되어 있으면 this.props.children 대신 폴백을 보여주므로, 고장난 Buggy는 다시는 실제로 렌더링되지 않습니다.

Self-check

  • Does clicking "Break it" show the fallback message instead of a blank/broken page?
  • Does the "Break it" button itself keep working after the error (it's outside the boundary)?
