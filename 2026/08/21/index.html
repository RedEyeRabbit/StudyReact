Day 8 — 중급 (Intermediate)

Error Boundaries / 에러 바운더리
🏠 Home / 홈 › Intermediate / 중급 › Day 8

Goal (30–40 min): Catch rendering errors in part of the tree so one broken component doesn't crash the whole app.

목표 (30~40분): 트리 일부에서 발생하는 렌더링 에러를 잡아서, 컴포넌트 하나가 고장 나도 앱 전체가 죽지 않도록 합니다.

English

1. Without a boundary
By default, if any component throws while rendering, React unmounts the entire app below the nearest root — a bug in one small widget can blank the whole page.

2. Error boundaries must be classes
As of React 18, there's no hook for this — you need a class component implementing static getDerivedStateFromError(error) (updates state so the next render shows a fallback) and optionally componentDidCatch(error, info) (for logging). Wrap it around whatever subtree you want protected.

3. What it does and doesn't catch
Catches errors thrown during rendering in child components. It does not catch errors in event handlers (use a regular try/catch there) or in async code like setTimeout.

한글

1. 바운더리가 없다면
기본적으로 렌더링 중 어떤 컴포넌트든 에러를 던지면, React는 가장 가까운 root 아래 전체 앱을 언마운트합니다 — 작은 위젯 하나의 버그가 페이지 전체를 하얗게 만들 수 있습니다.

2. 에러 바운더리는 반드시 클래스여야 함
React 18 기준으로 이를 위한 훅은 없습니다 — 클래스 컴포넌트에서 static getDerivedStateFromError(error)(다음 렌더링에서 폴백을 보여주도록 state를 갱신)를 구현하고, 선택적으로 componentDidCatch(error, info)(로깅용)도 구현해야 합니다. 보호하고 싶은 서브트리를 이걸로 감싸세요.

3. 잡는 것과 못 잡는 것
자식 컴포넌트의 렌더링 중 발생하는 에러를 잡습니다. 이벤트 핸들러 안의 에러(거기선 일반 try/catch를 쓰세요)나 setTimeout 같은 비동기 코드의 에러는 잡지 못합니다.
